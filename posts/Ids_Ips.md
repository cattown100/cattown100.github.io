# 침입 탐지 시스템(IDS)과 침입 방지 시스템(IPS) 정리

> 3기 미션 | IDS/IPS의 동작 원리, 유형, 활용 방법, 장단점, 차이점 학습

## 1. 들어가며

방화벽은 "누가 어느 포트로 들어올 수 있는가"를 정해진 규칙으로 허용하거나 막는다. 하지만 허용된 포트(예: 80, 443)로 들어오는 트래픽 안에 공격이 숨어 있으면 방화벽만으로는 알아채기 어렵다. 이런 공백을 메우기 위해 트래픽과 시스템의 **내용과 행위**를 들여다보는 보안 장비가 IDS와 IPS다.

- **IDS (Intrusion Detection System, 침입 탐지 시스템)**: 공격으로 의심되는 활동을 **탐지하고 알린다**.
- **IPS (Intrusion Prevention System, 침입 방지 시스템)**: 탐지에서 한 걸음 더 나아가 공격을 **자동으로 차단한다**.

한 줄로 요약하면 IDS는 "경보기", IPS는 "경보기 + 차단기"다.

---

## 2. IDS (침입 탐지 시스템)

### 2.1 동작 원리

IDS는 대체로 아래 흐름으로 동작한다.

1. **데이터 수집**: 네트워크 패킷, 시스템 로그, 프로세스·파일 변경 정보 등을 수집한다.
2. **전처리·분석**: 패킷을 재조합하고 프로토콜을 해석한다(예: TCP 스트림 재조립, HTTP 요청 파싱).
3. **탐지**: 정해 둔 탐지 방식(시그니처, 이상 징후 등)과 비교해 공격 여부를 판단한다.
4. **경보·기록**: 탐지되면 경보를 만들고 로그로 남긴다. 관리자나 SIEM 같은 중앙 시스템으로 전달된다.

IDS는 트래픽 흐름 **바깥에서 복사본을 보는 구조**(탭, 스위치 미러링/SPAN)라서 정상 통신에 영향을 주지 않는다. 대신 공격이 이미 지나간 뒤에 알리는 한계가 있다.

### 2.2 탐지 방식

| 탐지 방식 | 원리 | 장점 | 단점 |
|---|---|---|---|
| **시그니처(오용) 기반** | 알려진 공격의 패턴(문자열, 바이트 시퀀스, 규칙)과 일치하는지 비교 | 정확하고 오탐이 적음, 원인 파악이 쉬움 | 알려지지 않은 공격(제로데이)과 변형 공격에 약함, 규칙을 계속 갱신해야 함 |
| **이상(Anomaly) 기반** | 정상 행위의 기준선(baseline)을 학습하고 크게 벗어나는 행위를 탐지 | 새로운 유형의 공격도 탐지 가능 | 기준선 설정이 어렵고 오탐이 많음 |
| **프로토콜 분석 기반** | 프로토콜 명세(RFC 등)에서 벗어난 비정상 사용을 탐지 | 프로토콜 악용 공격에 효과적 | 프로토콜별 분석 구현이 필요하고 성능 부담이 있음 |
| **휴리스틱/행위 기반** | 여러 의심 행위의 조합이나 점수로 판단 (예: 짧은 시간에 로그인 실패 다수) | 시그니처 없이도 패턴 탐지 가능 | 임계값 튜닝이 어려움 |

실제 제품은 이 방식들을 섞어서 쓴다.

### 2.3 유형 (설치 위치 기준)

- **NIDS (Network-based IDS)**: 네트워크 구간의 트래픽을 감시한다. 한 지점에서 여러 호스트를 한꺼번에 볼 수 있다. 다만 암호화된 트래픽 내부는 보기 어렵다.
- **HIDS (Host-based IDS)**: 개별 서버·PC에 설치되어 해당 호스트의 로그, 파일 무결성, 프로세스, 시스템 콜 등을 감시한다. 암호화가 풀린 뒤의 행위까지 볼 수 있지만, 호스트마다 설치·관리해야 하고 호스트 자원을 쓴다.

대표 도구 예시는 다음과 같다.

- NIDS: Snort, Suricata, Zeek(네트워크 분석 프레임워크 성격)
- HIDS: OSSEC, Wazuh, Tripwire(파일 무결성)

## 3. IPS (침입 방지 시스템)

### 3.1 동작 원리

IPS는 IDS와 같은 탐지 엔진을 쓰되, 트래픽 경로 **중간(인라인, inline)에 위치**한다. 모든 패킷이 IPS를 통과하므로, 공격으로 판단되면 **전달하기 전에** 막을 수 있다.

탐지 후 취하는 대응 예시는 다음과 같다.

- 해당 패킷 **폐기(drop)**
- 해당 세션의 **연결 차단/리셋**(TCP RST 전송)
- 공격 출발지 IP를 일정 시간 **차단**
- 방화벽 규칙을 **동적으로 추가**
- 경보 및 로그 기록

### 3.2 유형

- **NIPS (Network-based IPS)**: 네트워크 경계나 내부 구간에 인라인으로 설치해 트래픽을 검사하고 차단한다.
- **HIPS (Host-based IPS)**: 호스트에서 비정상 프로세스 실행, 악성 행위, 시스템 콜 호출 등을 막는다.
- **WIPS (Wireless IPS)**: 무선 환경에서 불법 AP(Rogue AP), 무선 공격 등을 탐지·차단한다.
- **NBA (Network Behavior Analysis)**: 트래픽 흐름을 분석해 DDoS, 웜 확산 같은 이상 행위를 탐지·차단한다.

## 4. IDS와 IPS의 차이점

| 구분 | IDS | IPS |
|---|---|---|
| 핵심 역할 | 탐지와 경보 | 탐지와 차단 |
| 배치 방식 | 트래픽 복사본을 보는 **아웃오브밴드(out-of-band)** (탭, SPAN) | 트래픽 경로에 **인라인(in-line)** |
| 대응 | 수동적(관리자가 판단·조치) | 능동적(자동 차단) |
| 정상 통신 영향 | 거의 없음 | 있음(지연, 장애 시 서비스 중단 위험) |
| 오탐의 영향 | 불필요한 경보 증가 | 정상 트래픽 차단 → 서비스 장애 |
| 공격에 대한 시점 | 이미 발생한 공격을 사후에 인지 | 공격이 목적지에 닿기 전에 차단 가능 |
| 용도 | 모니터링, 포렌식, 위협 가시성 확보 | 실시간 방어 |

참고로 방화벽과도 구분할 수 있다. 방화벽은 주로 IP·포트·프로토콜 같은 **헤더 기준의 접근 통제**를 하고, IDS/IPS는 **페이로드와 행위까지 분석**한다. 요즘은 이 기능들이 하나의 장비에 합쳐진 차세대 방화벽(NGFW)이나 UTM에도 들어 있다.

## 5. 활용 방법

### 5.1 일반적인 구성 예

```
인터넷 ── 방화벽 ──[IPS(인라인)]── 내부망 스위치 ──┬── 서버/PC
                                       │
                                  (SPAN/Tap)
                                       │
                                     [IDS] ──→ 로그/경보 ──→ SIEM
```

- 경계 구간에는 IPS를 두어 알려진 공격을 자동으로 차단한다.
- 내부망에는 IDS(또는 탐지 모드의 IPS)를 두어 내부 이동(lateral movement), 이상 행위를 가시화한다.
- 중요한 서버에는 HIDS를 설치해 파일 변조와 계정 이상 행위를 확인한다.
- 모든 경보와 로그를 SIEM으로 모아 상관 분석하고 대응 절차(관제, 인시던트 대응)로 연결한다.

### 5.2 룰 예시 (Snort 형식)

SSH 로그인 시도가 짧은 시간에 반복되는 상황(무차별 대입 의심)을 탐지하는 규칙을 단순화해 보면 다음과 같다.

```
alert tcp any any -> $HOME_NET 22 (
  msg:"SSH brute force attempt";
  flags:S;
  detection_filter:track by_src, count 5, seconds 60;
  classtype:attempted-admin;
  sid:1000001; rev:1;
)
```

- `alert`: 탐지 시 경보. IPS 모드에서는 `drop`이나 `reject` 같은 동작으로 차단할 수 있다.
- `$HOME_NET 22`: 보호 대상 네트워크의 22번 포트(SSH)
- `detection_filter`: 같은 출발지에서 60초 안에 5회 이상이면 탐지
- `sid`: 규칙 고유 번호(사용자 정의 규칙은 보통 1000000번 이상을 사용)

실제 환경에서는 이 규칙 하나로 끝나지 않고, 로그인 실패 응답이나 허용 IP 예외 등을 함께 고려해 튜닝해야 한다.

## 6. 장단점

### IDS

**장점**
- 정상 트래픽 흐름에 영향이 거의 없다(성능 영향, 장애 전파 위험이 작음).
- 오탐이 나도 서비스가 끊기지 않는다.
- 사고 분석(포렌식)과 위협 가시성 확보에 유용하다.

**단점**
- 탐지만 하므로 공격을 즉시 막지 못한다. 대응이 사람의 속도에 의존한다.
- 경보가 많아지면 **경보 피로(alert fatigue)** 로 중요한 경보를 놓칠 수 있다.
- 알려지지 않은 공격이나 변형 공격은 놓칠 수 있다(오탐/미탐 문제).

### IPS

**장점**
- 알려진 공격을 자동으로, 실시간으로 차단한다.
- 관리자의 즉각적인 개입 없이 방어할 수 있다.
- 취약점 패치 전까지 가상 패치처럼 임시 방어 수단으로 쓸 수 있다.

**단점**
- 오탐 시 정상 서비스가 차단될 수 있다.
- 인라인 구조라 지연과 병목, 단일 장애점(SPOF)이 될 수 있다.
- 튜닝과 유지 관리 비용이 크다.

## 7. 한계와 우회 가능성

IDS/IPS가 만능은 아니다. 아래와 같은 한계를 이해하고 있어야 한다.

- **암호화 트래픽**: HTTPS처럼 암호화된 페이로드는 그대로는 검사할 수 없다. 복호화(SSL/TLS 인스펙션) 장비와 연계하거나 호스트 기반 탐지를 병행해야 한다.
- **회피 기법**: 패킷 단편화(fragmentation), 인코딩 변형, 프로토콜 모호성 등으로 탐지를 피하려는 시도가 있다. 이를 막으려면 엔진이 패킷을 재조합하고 정규화(normalization)해서 호스트와 같은 방식으로 해석해야 한다.
- **제로데이와 미지의 공격**: 시그니처 기반 방식은 알려진 공격에 강하고 새로운 공격에 약하다. 이상 탐지와 행위 기반 탐지, 위협 인텔리전스를 보완적으로 써야 한다.
- **오탐/미탐 균형**: 민감하게 설정하면 오탐이 늘고, 느슨하게 설정하면 미탐이 늘어난다. 환경에 맞는 지속적인 튜닝이 필요하다.

그래서 IDS/IPS는 방화벽, 백신/EDR, 로그 분석(SIEM), 패치 관리 등과 함께 **다계층 방어(Defense in Depth)** 의 일부로 운영하는 것이 맞다.
