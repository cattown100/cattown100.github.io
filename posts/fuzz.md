# 퍼징(Fuzzing)과 여러 가지 퍼저 정리

## 1. 퍼징이란?

**퍼징(Fuzzing)** 은 프로그램에 **비정상적이거나 예상치 못한 입력을 대량으로 자동 주입**해서 크래시·메모리 오류·비정상 동작 같은 버그를 찾는 테스트 기법이다. 입력을 만들어 넣는 도구를 **퍼저(Fuzzer)** 라고 부른다.

사람이 일일이 테스트 케이스를 짜면 개발자가 생각한 범위 안에서만 테스트하게 된다. 퍼징은 사람이 떠올리지 못한 이상한 입력을 기계적으로 쏟아부어 숨은 버그를 찾는다. 특히 C/C++처럼 메모리를 직접 다루는 언어에서 버퍼 오버플로, Use-After-Free, 정수 오버플로 같은 **메모리 손상 취약점**을 찾는 데 많이 쓰인다.

### 기본 동작 흐름

```
[초기 입력(seed)] → [입력 생성/변형] → [대상 프로그램 실행]
        ↑                                      │
        └──── 흥미로운 입력 저장 ←── [결과 관찰: 크래시? 새 코드 실행?]
```

1. 초기 입력을 준비한다.
2. 입력을 만들거나 변형한다.
3. 대상 프로그램에 넣고 실행한다.
4. 크래시, 타임아웃, 새로운 동작 등을 관찰한다.
5. 크래시가 나면 그 입력을 기록하고, 새로운 코드 경로를 밟은 입력은 다음 변형의 재료로 저장한다.

## 2. 퍼징의 종류

퍼징은 분류 기준에 따라 여러 방식으로 나눌 수 있다.

### 2.1 대상 프로그램을 얼마나 아는가: 블랙박스 / 그레이박스 / 화이트박스

| 구분 | 내용 | 특징 |
|---|---|---|
| **블랙박스 퍼징** | 프로그램 내부를 모르고 입력과 출력(크래시 여부)만 본다 | 구현이 간단하고 빠르지만 깊은 코드까지 도달하기 어렵다 |
| **그레이박스 퍼징** | 코드 커버리지 같은 **가벼운 내부 정보**를 활용한다 | 효율과 성능의 균형이 좋아 현재 가장 널리 쓰인다 |
| **화이트박스 퍼징** | 소스 코드, 실행 경로를 분석해 입력을 만든다 | 어려운 분기도 뚫을 수 있지만 느리고 확장성이 낮다 |

### 2.2 입력을 만드는 방식: 변이 기반 / 생성 기반

- **변이(Mutation) 기반**: 기존 정상 입력을 비트 반전, 바이트 삽입·삭제, 값 교체 등으로 **조금씩 변형**한다. 입력 형식을 몰라도 쓸 수 있다.
- **생성(Generation) 기반**: 입력 형식을 정의하고 그 규칙에 맞게 **처음부터 입력을 생성**한다. 형식이 엄격한 입력에서 깊은 로직까지 도달하기 쉽다.

### 2.3 피드백 사용 여부: 커버리지 기반 퍼징

**커버리지 기반(Coverage-guided) 퍼징**은 프로그램에 계측을 넣어 입력이 **새로운 코드 경로** 를 실행했는지 확인한다. 새 경로를 연 입력은 저장해서 다음 변이의 재료로 쓰고 그렇지 않은 입력은 버린다. 이 피드백 루프 덕분에 무작위 입력만 넣을 때보다 훨씬 깊은 곳까지 도달한다. 현대 퍼저의 중심 개념이다.

### 2.4 그 밖의 분류

- **방향성(Directed) 퍼징**: 전체 커버리지가 아니라 **특정 코드 위치** 에 도달하는 것을 목표로 한다.
- **상태 기반(Stateful) 퍼징**: 네트워크 서버처럼 여러 메시지를 주고받는 프로토콜에서, 통신 **상태 순서**까지 고려한다.
- **하이브리드 퍼징**: 퍼징과 심볼릭/콘콜릭 실행을 섞는다. 퍼저가 막히는 조건 분기를 심볼릭 실행으로 풀어 준다.

### 2.5 퍼징의 짝꿍: Sanitizer

퍼징은 크래시가 나야 버그를 알 수 있다. 하지만 메모리 오류 중에는 크래시 없이 조용히 넘어가는 것이 많다. 그래서 컴파일 시 **Sanitizer**를 함께 켜서 오류를 즉시 잡아낸다.

- **ASan (AddressSanitizer)**: 힙/스택 버퍼 오버플로, UAF 등 탐지
- **UBSan**: 정의되지 않은 동작(정수 오버플로, null 역참조 등) 탐지
- **MSan**: 초기화되지 않은 메모리 사용 탐지

## 3. 대표적인 퍼저들

### 3.1 AFL / AFL++ (그레이박스, 변이 기반)

- 컴파일 시 코드를 계측해 **커버리지 피드백**을 받는 대표적인 퍼저다. 원조 AFL은 개발이 멈췄고 커뮤니티가 이어받아 발전시킨 **AFL++** 가 현재 표준처럼 쓰인다.
- 소스가 없을 때는 QEMU 모드 등으로 바이너리를 계측할 수도 있다.
- 입력 파일을 받는 프로그램에 적용하기 쉽고 사용 사례와 자료가 가장 많다.

### 3.2 libFuzzer (인프로세스, 커버리지 기반)

- LLVM에 포함된 퍼저로, 대상 프로그램과 **같은 프로세스 안에서** 함수를 반복 호출한다. 프로세스를 매번 새로 띄우지 않아 속도가 매우 빠르다.
- 퍼징할 함수 하나를 **하니스** 로 만들어 연결한다. 라이브러리 단위 테스트에 적합하다.
- ASan 등 Sanitizer와 함께 쓰는 것이 일반적이다.

### 3.3 honggfuzz

- 구글 쪽에서 개발한 커버리지 기반 퍼저로 멀티 프로세스/멀티 스레드를 지원하고 하드웨어 피드백(예: 일부 CPU 기능 활용)도 쓸 수 있다.
- 설정이 비교적 단순하고 크래시 분석 기능이 잘 갖춰져 있다.

### 3.4 Peach / boofuzz (생성 기반, 프로토콜 퍼징)

- 입력 **형식과 프로토콜 구조를 직접 정의**해서 입력을 생성하는 퍼저다.
- 커버리지 피드백보다는 **구조를 아는 입력**으로 프로토콜의 깊은 로직을 두드리는 데 강하다. 대신 모델을 작성하는 비용이 든다.

### 3.5 Syzkaller (커널, 시스템 콜 퍼징)

- 구글의 **리눅스 커널 퍼저**로, 시스템 콜 호출 시퀀스를 만들어 커널을 퍼징한다. 시스템 콜 형식을 기술한 정의 파일을 기반으로 생성하고, 커널 커버리지(KCOV)를 피드백으로 사용한다.
- 커널은 크래시가 나면 시스템 전체가 영향을 받기 때문에, 가상 머신 안에서 돌리고 자동으로 재시작하는 구조를 쓴다.

### 3.6 Windows 쪽 퍼저 (WinAFL, Jackalope 등)

- **WinAFL**: AFL의 개념을 Windows에 가져온 퍼저로, 소스가 없는 Windows 바이너리의 특정 함수를 반복 실행하며 커버리지를 얻는다. (동적 계측 프레임워크 사용)
- **Jackalope**: Windows와 macOS 등에서 소스 없는 바이너리를 대상으로 커버리지 기반 퍼징을 하는 도구다.
- 이들은 파일 파서, 문서 뷰어 같은 **사용자 모드 프로그램**에 주로 쓴다.
- 윈도우 **커널 드라이버**의 취약점은 보통 IOCTL 인터페이스(DeviceIoControl)를 통해 입력이 들어오기 때문에 IOCTL 코드와 입력 버퍼를 변조해 호출하는 방식의 드라이버 퍼징을 따로 한다. 학습 중인 HEVD 같은 취약 드라이버가 이 분야의 연습 대상이다.

### 3.7 언어별 퍼저

- **cargo-fuzz** (Rust, libFuzzer 기반), **go-fuzz / Go 내장 퍼징**, **Jazzer** (Java/JVM), **Atheris** (Python) 등 언어별로 libFuzzer 스타일의 퍼저가 있다.
- 메모리 안전 언어도 패닉, 무한 루프, 로직 오류를 찾는 데 퍼징이 쓰인다.

### 3.8 대규모 운영: OSS-Fuzz / ClusterFuzz

- **OSS-Fuzz**는 오픈소스 프로젝트를 대상으로 퍼저를 지속적으로 돌려 주는 구글의 서비스이고 그 기반 인프라가 **ClusterFuzz**다. 퍼저는 한 번 돌리고 끝이 아니라 **지속적으로 돌리는 것**이 중요하다는 점을 보여 준다.

## 4. 퍼저 비교

| 퍼저 | 대상 | 방식 | 특징 | 적합한 경우 |
|---|---|---|---|---|
| **AFL++** | 프로그램 전반 | 그레이박스, 변이 기반, 커버리지 | 자료가 많고 범용적, 소스 없을 땐 QEMU 모드 | 입문, 파일 파서, 범용 C/C++ 프로그램 |
| **libFuzzer** | 라이브러리 함수 | 인프로세스, 커버리지 | 매우 빠름, 하니스 작성 필요 | 소스가 있고 함수 단위로 테스트할 때 |
| **honggfuzz** | 프로그램 전반 | 커버리지, 멀티 프로세스 | 설정 간단, 크래시 분석 기능 | 빠르게 병렬로 돌릴 때 |
| **Peach / boofuzz** | 파일 포맷, 네트워크 프로토콜 | 생성 기반(모델 정의) | 구조를 아는 입력 생성, 모델 작성 비용 | 프로토콜, 형식이 엄격한 입력 |
| **Syzkaller** | 리눅스 커널 | 시스템 콜 시퀀스 생성, 커널 커버리지 | VM 기반, 자동 재시작 | 커널 취약점 탐색 |
| **WinAFL / Jackalope** | Windows 바이너리 | 커버리지 | 소스 없는 Windows 프로그램 가능 | Windows 사용자 모드 프로그램 |
| **언어별 퍼저** | Rust, Go, Java, Python 등 | libFuzzer 스타일 | 언어 생태계와 통합 | 해당 언어 프로젝트 |
